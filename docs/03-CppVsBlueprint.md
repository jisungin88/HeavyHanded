# 03. C++ 와 블루프린트 역할 분담

> 이 문서는 **커밋되어 확인 가능한 코드**를 기준으로 쓴다.
> 경계는 이미 `UPROPERTY` / `UFUNCTION` 특성으로 코드에 박혀 있다. 이 문서는 그것을 성문화한다.

---

## 1. 이 문서의 범위

**여기서 정하는 것**

- 어떤 코드를 C++ 로 쓰고 어떤 것을 BP 로 쓰는가
- 경계를 넘기는 장치 5종과 각각의 용도
- BP 에 **의도적으로 열지 않는 것**과 그 이유
- 새 기능을 만들 때 어느 쪽을 건드리는가

**여기서 정하지 않는 것**

| 주제 | 문서 |
|---|---|
| 에셋 네이밍, 폴더 구조 | [05-Conventions.md](05-Conventions.md) |
| 데이터 자산(DataTable · Settings) 상세 | [04-DataManagement.md](04-DataManagement.md) |
| 각 시스템에서 실제로 무엇을 만드는가 | `systems/*.md` |

> 코드 주석의 `(컨벤션 4-3)`, `팀 컨벤션 2-2 예시` 같은 번호 참조는 옛 Notion 페이지의 절 번호다.
> 대응하는 현재 위치는 [05-Conventions.md](05-Conventions.md) 맨 위 표에 있다.
> `4-3` 이 가리키는 "로직은 C++, BP 는 값만" 규칙이 이 문서 6장이다.

## 2. 판단 기준

### 한 문장

> **C++ 는 "무슨 일이 일어났는가"를 정한다. BP 는 "그게 어떻게 보이는가"를 정한다.**

### 판정 질문

새로 무언가를 BP 에 열까 말까 고민될 때, 순서대로 물어본다.

**1. 이게 틀리면 플레이어마다 다른 결과가 나오는가?**
그렇다면 C++ 다. 서버 권위 판정은 예외 없이 C++ 이다 ([02-Networking.md](02-Networking.md) 3장).

**2. 이게 없어도 게임이 성립하는가?**
없어도 성립한다면(파티클, 사운드, 색 전환, 화면 흔들림) BP 다.
연출은 놓쳐도 게임 상태가 어긋나지 않는다.

**3. 아티스트·기획자가 반복해서 만질 값인가?**
그렇다면 BP 에 노출한다. 메시, 수치, 몽타주, 색상.

**4. 매 프레임 또는 매 충돌마다 도는가?**
그렇다면 C++ 다. BP 호출은 `ProcessEvent` 를 타므로 호출 자체에 비용이 있다
(`INoiseListener::GetListenerLocation` 주석 참조 — 그래서 소음 서브시스템은
**값싼 거리 컬링을 먼저 하고 나서야** 이 함수를 부른다).
물리 낙하 1회에 `OnHit` 이 5~15회 발생한다는 것을 기억할 것.

## 4. 경계를 넘기는 장치 5종

현재 코드에 쓰이는 것은 이 다섯 가지뿐이다. **여섯 번째를 늘리려면 근거와 함께 여기 추가할 것.**

| 장치 | 방향 | 용도 | 현재 사용 |
|---|---|---|---|
| `BlueprintImplementableEvent` | C++ → BP | **연출 훅.** C++ 가 부르고 BP 가 그린다 | 7개 |
| `BlueprintNativeEvent` | C++ → BP (기본 구현 있음) | BP 가 동작을 **바꿀 수도** 있게 | 2개 |
| `UCLASS(Abstract)` | 구조 | BP 서브클래스를 **강제**한다 | 위젯 2종 |
| `UCLASS(Blueprintable)` | 구조 | BP 서브클래스를 **허용**한다 | `ALootBase` |
| `meta = (BlueprintSpawnableComponent)` | 구조 | BP 에서 컴포넌트를 붙일 수 있게 | 3개 |

### `BlueprintImplementableEvent` — 연출 훅

**이 프로젝트에서 가장 중요한 장치다.** 7개 전부가 같은 형태를 지킨다 —
C++ 가 판정을 끝낸 **뒤에** 호출되고, BP 는 표시만 한다.

| 함수 | 클래스 | 주석에 명시된 계약 |
|---|---|---|
| `OnValueChanged` | `ALootBase` | "숫자 위젯·머티리얼 변화 같은 표시만 한다. **판정은 이미 C++ 에서 끝났다**" |
| `OnDamageAccumulated` | `ULootDurabilityComponent` | "BP 는 여기서 머티리얼·메시·사운드만 바꾼다. **판정은 이미 C++ 에서 끝났다**" |
| `OnBroken` | `ULootDurabilityComponent` | "파편·사운드 연출용. 이 시점에 메시는 이미 숨겨져 있다" |
| `OnGaugeUpdated` | `UAlertGaugeWidget` | "바 채우기와 보간을 여기서 한다" |
| `OnLevelUpdated` | `UAlertGaugeWidget` | "색 전환·펄스·경보 점멸을 여기서 한다" |
| `OnPerceptionUpdated` | `UPerceptionMeterWidget` | "원형 채우기와 보간을 여기서 한다" |
| `OnMeterVisibilityChanged` | `UPerceptionMeterWidget` | "페이드 인/아웃을 여기서 한다" |

**새 연출 훅을 만들 때도 이 형태를 지킨다** — 판정이 끝난 뒤에 부르고, 결과를 인자로 넘긴다.
BP 가 판정에 참여할 여지를 남기지 않는다.

> BP 훅에서 게임 상태를 바꾸지 말 것. 훅은 클라이언트에서도 돌고,
> 거기서 상태를 바꾸면 서버와 갈린다. 훅은 **읽고 그리기만** 한다.

### `BlueprintNativeEvent` — BP 가 동작을 바꿀 수 있는 지점

`INoiseListener` 의 두 함수뿐이다. 헤더 주석에 이유가 있다 —
*"경비 BP 에서 직접 오버라이드할 수 있게 하기 위해서."*

**대가가 있다.** 호출 자체가 `ProcessEvent` 를 타므로, `UNoiseSubsystem` 은
액터 위치로 값싼 1차 거리 컬링을 한 뒤에야 `GetListenerLocation()` 을 부른다.
그래서 이 함수에는 **계약**이 붙어 있다 — 반환 지점은 소유 액터 위치에서 500cm 안이어야 한다.
어기면 반경 경계의 청취자가 조용히 걸러지고, 쉬핑 빌드에서는 아무 신호도 없다.

**BlueprintNativeEvent 를 새로 만들 때는 이런 계약이 필요한지 먼저 생각할 것.**
가능하면 `BlueprintImplementableEvent`(연출 전용)로 충분한지 다시 본다.

### `UCLASS(Abstract)` vs `UCLASS(Blueprintable)`

- **`Abstract`** — BP 서브클래스가 **반드시** 있어야 한다. 위젯이 여기 해당한다.
  C++ 베이스가 데이터 바인딩·구독·해제를 하고, `WBP_*` 가 비주얼을 전부 만든다.
  C++ 클래스를 직접 스폰하면 화면에 아무것도 안 나오므로 `Abstract` 로 막는다.
- **`Blueprintable`** — BP 서브클래스를 **허용**한다. `ALootBase` 가 여기 해당한다.
  C++ 만으로도 동작하지만, 메시와 수치를 지정하려면 BP 서브클래스가 필요하다.

## 5. BP 에 열지 않는 것

**열지 않은 것에는 반드시 이유가 있다. 열어달라고 하기 전에 여기를 볼 것.**

| 대상 | 왜 막았나 |
|---|---|
| `FOnLootImpactSignature` (`ALootBase`) | BP 에서 소음 판정 로직을 짜는 것을 **원천 차단**. 또한 `TWeakObjectPtr` 를 담고 있어 BP 에 열면 수명 관리가 깨진다 |
| `FOnNoiseReported` (`UNoiseSubsystem`) | 감쇄 전 이벤트. 서버 권위 계산에만 쓰인다 |
| `UAlertComponent::GetNoiseContribution()` | 서버 전용 집계 맵. 클라이언트에서는 항상 비어 있다. `UFUNCTION` 반환 타입에 `TObjectPtr` 를 쓸 수 없기도 하다 |
| 권위 판정 함수 (`HasServerAuthority`) | 자유 함수. BP 에서 우회할 수 있으면 게이트가 아니다 |

### 규칙

> **"BP 에서 구독할 수 없게 만드는 것"이 "BP 에서 하지 마세요"라는 문서 한 줄보다 확실하다.**

새 시스템에서 서버 권위 이벤트를 만들 때는 **다이내믹 델리게이트가 아닌
C++ 전용 멀티캐스트(`DECLARE_MULTICAST_DELEGATE_*`)** 를 기본으로 한다.
UI 가 구독해야 하는 것만 `DECLARE_DYNAMIC_MULTICAST_DELEGATE_*` 로 연다.

## 6. 데이터는 BP, 로직은 C++

`FLootPhysicsData` 주석에 원칙이 그대로 있다 —
**"값은 블루프린트에서 지정하고, 로직은 C++ 에서만 소비한다."**

### 진짜 이유는 병합 비용이다

이 규칙이 "기획자가 코드 없이 조정할 수 있게" 정도로 읽히기 쉬운데, 팀 컨벤션이 든 이유는 더 실제적이다 —

> **C++ 은 diff 와 병합이 가능하지만 블루프린트는 불가능하므로, 충돌 비용이 비교할 수 없이 낮다.**
> 블루프린트는 C++ 클래스를 상속해 **값(수치·메시·사운드)만 지정하는 껍데기**로 유지한다.

`.uasset` 은 바이너리다. 코드 충돌은 해결할 수 있지만 **에셋 충돌은 한쪽 작업이 그대로 소실된다.**
6명이 동시에 작업하는 리포에서 이건 이론적 위험이 아니다.
BP 에 로직을 넣을수록 두 사람이 같은 에셋을 열 확률이 올라간다.

### 적용 방법

- C++ 는 `USTRUCT` 로 **모양**을 정의하고 기본값만 넣는다
- BP 서브클래스가 **실제 값**을 채운다
- C++ 가 그 값을 읽어 계산한다

```cpp
// C++ 는 모양과 제약만 정한다
UPROPERTY(EditAnywhere, BlueprintReadOnly, Category = "Loot|Throw",
    meta = (ClampMin = "0.0"))
float ThrowSpeed = 900.f;
```

### `BlueprintReadOnly` 를 기본으로 한다

`FLootPhysicsData` 의 모든 필드가 `BlueprintReadOnly` 다.
BP 는 **에디터에서 값을 지정**하지만 **런타임에 바꾸지는 못한다.**

런타임 변경이 필요하면 C++ 함수를 거치게 한다. 그래야 복제·검증·소음 발행이 같이 따라온다.

### 값으로 표현할 수 있는 것을 코드로 만들지 않는다

같은 주석에 좋은 예가 있다 — 무거운 물건이 덜 날아가는 것을
"무게에 따라 분기하는 코드"가 아니라 **`ThrowSpeed` 값을 낮게 잡아** 표현한다.
임펄스는 질량을 곱해 만들기 때문에, 데이터만 바꿔도 의도한 결과가 나온다.

**"행동이 아니라 데이터로"** — 이렇게 하면 기획자가 코드 없이 조정할 수 있다.

## 7. 순수 BP 에셋 — 유형별 규칙

아래 유형은 **C++ 대응 클래스를 만들지 않는다.** BP/에셋으로만 만든다.

| 유형 | 이유 |
|---|---|
| `GameplayEffect` | 지속시간·모디파이어·부여 태그가 전부 데이터다. C++ 클래스를 만들 이유가 없다 |
| `InputAction` · `InputMappingContext` | Enhanced Input 의 데이터 자산 |
| `BehaviorTree` · `Blackboard` | 트리 구조 자체가 에셋. **단, 태스크·데코레이터·서비스 노드는 C++** |
| `AnimBlueprint` · `AnimMontage` · `BlendSpace` | 애니메이션 |
| `Widget Blueprint` (`WBP_*`) | 레이아웃과 위젯 애니메이션 |
| `Material` · `Niagara System` | 렌더링 |
| `GameplayCue Notify` | 연출. `Config/Tags/Cue.ini` 의 태그에 대응 |

### 예외 — BehaviorTree 는 반씩 나뉜다

트리 **구조**(`BT_Guards`, `BB_Guards`)는 에셋이지만,
**노드**(`BTTask_*`, `BTDecorator_*`, `BTService_*`)는 전부 C++ 다. 현재 7개.

이유 — 노드 안에 판정 로직이 들어가기 때문이다.
게이지 계산, 순찰 지점 선택, 경계도 조회는 BP 노드로 만들면 디버깅과 복제 검증이 어려워진다.
**BT 에서 새 판정이 필요하면 C++ 노드를 만들고, 트리에서 조립만 BP 로 한다.**

## 8. 유형별 작업 가이드

*"이걸 만들려면 어디를 건드리나."* 언어 선택만 다룬다. 실제 절차는 각 `systems/` 문서에 있다.

| 만들 것 | C++ | BP / 에셋 |
|---|---|---|
| **새 노획물 종류** (석상, 도자기) | 보통 불필요 | `ALootBase` 서브클래스 → 메시 + `FLootPhysicsData` 값 |
| **새 노획물 *거동*** (불안정형 굴러감) | 필요. 컴포넌트 추가 | 값 지정 |
| **새 어빌리티** | `UBaseGameplayAbility` 파생 클래스 | `GA_*` 서브클래스 → 몽타주 · Cue · 쿨다운 GE |
| **어빌리티 수치만 조정** | 불필요 | `GE_*` 에셋 |
| **새 HUD 위젯** | 상태를 읽고 구독하는 `Abstract` 베이스 | `WBP_*` 서브클래스가 비주얼 전부 |
| **위젯 색·레이아웃만 변경** | 불필요 | `WBP_*` + `UUISettings` |
| **새 경비 타입** | 보통 불필요 | `BP_GuardBase` 파생 → 메시 + Perception 파라미터 |
| **새 경비 *행동*** | BT 노드 C++ 추가 | `BT_Guards` 에서 조립 |
| **새 소음원** | `UNoiseEmitterComponent` 부착 + `ReportNoise` 호출 | `Config/Tags/Noise.ini` 태그 + `DT_NoiseProfiles` 행 |
| **소음 수치 조정** | 불필요 | `DT_NoiseProfiles` |
| **새 감지 장치 · 방해 요소** | `INoiseListener` 구현 클래스 | 메시 + 파라미터 |
| **새 연출** | `BlueprintImplementableEvent` 훅 (없다면) | Niagara · 사운드 · 머티리얼 |

**표에서 "보통 불필요"가 많은 것이 정상이다.** C++ 를 건드려야 하는 상황이 잦다면
그건 데이터로 표현할 수 있는 것을 코드로 만들고 있다는 신호다 (6장 참조).

## 9. 이 문서를 고쳐야 할 때

- 경계를 넘기는 **여섯 번째 장치**를 도입하려면 4장에 먼저 추가하고 근거를 적는다
- BP 에 무언가를 새로 열 때는 **2장 판정 질문 4개를 먼저 통과시킨다**
- 5장 차단 목록에서 무언가를 열자는 제안이 나오면, **막았던 이유가 아직 유효한지** 확인한다.
  유효하지 않게 됐다면 열되, 이유가 왜 사라졌는지 여기 적는다
